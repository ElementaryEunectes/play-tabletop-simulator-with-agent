# HARNESS_HOME_AGENTS.template.md —— 放到 harness home 的"通用纪律"模板

> **这份不是给本仓库读的**（本仓库的项目纪律在 `AGENTS.md`）。它是**跨项目那份**的可版本化源。
>
> **放哪**：`$DSH_HOME\AGENTS.md`（DSH 的"用户全局"指令文件 —— **每次请求都注入**，所以只放放之四海皆准的条目）。
> **怎么装**：改本文件 `---` **以下的正文** → 整段覆盖到 `$DSH_HOME\AGENTS.md`（该路径在工作区之外 ⇒ 需要**一次提权**）。
> 本仓库的 `tts\tests\test_agents_hygiene.ps1` 会核对"全局那份与这里的正文逐字一致"（漂移检查）—— 装完跑一次它。
>
> ⛔ 模板正文里不许出现任何机器专属内容（用户名、绝对路径、本机端口）。那些属于**项目目录下的 `AGENTS.local.md`**（overlay，不进仓库）。

## 隔离机制（DSH 的实际规则，2026-10-08 读源码确认）—— **这段不进正文，别拷**

- **注入什么**：① `$DSH_HOME\AGENTS.md`（用户全局，**文件名是常量**，存在就第一个加，**与 cwd 无关**）
  ② **项目根 → cwd 的项目链**（项目根 = 从 cwd 向上第一个含 `.git` 的目录；**一个都没有时项目根 = cwd 自身**），
  每级找 `AGENTS.md` / `CLAUDE.md`，再找 `AGENTS.local.md` / `CLAUDE.local.md`。
- **去重只有两种**：**绝对路径**去重（同一份文件不会算两次）＋ **同目录内**去掉 trim 后内容相同的兄弟文件。
  源码原话：**跨目录即使内容完全相同也绝不合并**。最后按**字节预算**渲染（超了先丢"更宽泛的"，即离 cwd 更远的）。
  ⇒ "只有通用槽"的会话 = 从**仓库外、且该目录没有那四个候选文件**的地方起会话（或 cwd 设成 `$DSH_HOME` 本身：链扫到的是同一绝对路径，被去重）。
- ⛔ **没有"忽略用户全局那份"的开关**（`USER_GLOBAL_FILE` 是常量，`instructionFileCandidates` 只管项目链）
  ⇒ 想让全局那份不参与注入，有**三条**（推荐度序）：
  ① per-project profile（`tts\dsh_profile.ps1`）：`$DSH_HOME` 指到 `%LOCALAPPDATA%\dsh-profiles\<项目>\`，条目是 junction / hard link 指回共享的家、**故意不放 `AGENTS.md`** ⇒ 全局槽**零注入**且**不搬数据**（实测 7,759 → 4,835 B/请求）；
  ② `$DSH_HOME` 里没有它（删 / 改名）—— 最省事，但**所有项目**都没了那份通用纪律；
  ③ **把 `$DSH_HOME` 钉到项目根**（两槽同一绝对路径 ⇒ 去重成一份），代价是把 harness 的家（sessions / 凭据）搬进项目。
- **三份归位**：通用（跨项目）→ **本文件的正文** · 项目 → 该项目的 `AGENTS.md` · **机器专属 → 该项目的 `AGENTS.local.md`**（overlay，不进仓库）。
  ⚠️ 用了 profile 的项目**注入不到本文件** ⇒ 它每天要用的平台要点必须就近写进**它自己的** `AGENTS.md` / `AGENTS.local.md`。
- 改文件会触发**再注入**（会话中途改它，harness 会推一条变更提醒把新内容补进来）⇒ 每次改都在为它付钱。

# AGENTS.md —— 平台宪章（**跨项目不变**）

> **每次请求都注入并计费** ⇒ 只放**放之四海皆准、且 harness 自带提示里没有**的条目。
> ⛔ 不放任何单一项目的领域知识（某项目怎么干活、某局的坐标/规则/状态）—— 那些放**该项目自己的文档**；**发现混进来就立刻搬走**。
> 可版本化源：仓库 `tts\docs\HARNESS_HOME_AGENTS.template.md`（改那份 → 取 `---` 以下的正文拷到这里）。
> 三份文件怎么归位 · 注入顺序与去重 · 各类工作区的注入量 ⇒ **见该模板头部**（本文件不复述机制）。

## 1. 文件与编码

- **含中文的 `.ps1` 必须 UTF-8 带 BOM**：PS 5.1 把无 BOM 当 ANSI 读 ⇒ 中文变乱码 ⇒ **语法报错、脚本"秒挂"**（编辑工具常悄悄丢 BOM）。
  ⇒ **改完任何 `.ps1` 都用真解析器校验一次**（项目里若有 `check_ps1.ps1` 这类工具就直接用它），别只靠"能跑起来"。
- 一次性脚本**注释与输出尽量 ASCII**；改前先 read，**一次只动一处**，改完回读。

## 2. 执行

- 跑脚本一律 `powershell -NoProfile -ExecutionPolicy Bypass -File '<绝对路径>'`（`& xxx.ps1` 可能被策略挡下）。
- **沙箱只允许写工作区**；写外面报 `[sandbox: file access denied]` ⇒ 那是策略不是 bug，**一次提权重试**，别硬绕。
- **工具壳是 Windows PowerShell 5.1** ⇒ 直接 `Get-Content` / `Select-String` 读中文会按 ANSI 解码、打印成**乱码**（文件没坏）⇒ 加 `-Encoding UTF8` 或 `[IO.File]::ReadAllText`。
- **判端口用 `netstat -ano | findstr :<port>`**（`Get-NetTCPConnection` 在本沙箱会假报"没人在听"）。
- 长任务用**后台作业**；等外部事件靠**通知 / 哨兵**，不要 `sleep` 轮询。

## 3. 操作纪律（**只留 harness 自带提示里没有的**）

1. 写操作前**先打印目标路径 / 目标值**核对，再发命令。
2. **回复尽量短**：先结论与下一步。
3. ⛔ **改代码前先提交或备份**；⛔ **绝不用批量字符串替换改活代码**（替换串被展开、引号被吃、BOM 会叠 —— 曾一次连坏 22 个脚本）。

## 4. 代码一致性（**一个事实只有一处真源**）

- ⭐ **一处定义、他处引用**：判定 / 常量 / 路径 / 阈值只在**一处**定义，别处引用它；**文档也不复述判定**，只留指针（"见 X §N"）。
  （反例：一条"某按钮能不能点"的判定散在 **9 份文档 19 处** ⇒ 改一处必漂移。**同一事实写两遍 = 迟早不一致**。）
- **入口收口**：路径与配置走**单一入口**（如项目根的 `config.ps1`）；⛔ 业务脚本里不写死绝对路径 / 用户名 / 项目名 / 端口。
- **命名 + 别名自检**：函数用**动词-名词**；写完先 `Get-Alias <名字>` —— `rd del erase rm rmdir md cd ls mv cp cat echo` 是内置别名，且**别名优先级高于函数**（叫 `Rd` 的"读取"函数实际执行 `Remove-Item`，真删过文件）。
- **阈值按字符、体积按字节**：`ReadAllText().Length` 是**字符**数，`(Get-Item).Length` 是**字节**数 —— 混用 ⇒ 守卫要么误拦、要么形同虚设。
- **`&` 调别人的脚本前，确认它不 `exit`**：`exit` 会终止**调用者的整个会话** ⇒ 工具 / 库脚本用 `throw`，不要用 `exit`。
- **能追加就别重写**：`Add-Content` 按构造不可能截断；必须重写时 ⇒ `$ErrorActionPreference = 'Stop'` ＋ **先全量校验锚点再统一写盘** ＋ **写前兜底"内容短于 N 字符就拒绝写"**。
- **门禁绿了才提交**：⛔ 别把"跑测试"与"提交"无条件串成一条命令（会带着红灯提交）。
