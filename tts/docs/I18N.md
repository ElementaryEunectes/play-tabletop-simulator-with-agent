# I18N.md —— 给一款**外文 mod** 做本地化（机翻）时读我

> **什么时候读我**：你想让中文玩家直接玩一款英文/日文工坊 mod 的时候。**读这一次就够了**（不是每回合）。
> ⭐ **本仓库不内置任何翻译引擎** —— 它只提供**接口**，引擎你自己挂（本地引擎 / 手工 / 云都行）。外部项目候选 ⇒ `PRIOR_ART.md` §9.3；工具清单 ⇒ `MAINTENANCE.md` §5。

## 0. 架构：两段是我们的，中间一段是你的

```
Saves\TS_AutoSave*.json                  ← 游戏写出来的自动存档（只读它）
        │  【导出】读存档 · 抽文本字段
        ▼
text.tsv        id <TAB> guid <TAB> field <TAB> source      ← ⭐ 接口就在这个文件
        │  【翻译】你的引擎 / 手工 / 任何东西
        ▼
text.zh.tsv     id <TAB> guid <TAB> field <TAB> target
        │  【回写】字符串级替换 · 回读校验
        ▼
patched.json    → 放回 Saves\ → 在 TTS 里 Save & Load
```

### 接口契约（唯一的约定）

翻译器 = **吃 TSV、吐 TSV、只填最后一列** 的任何东西。

- **输入**列：`id` · `guid` · `field` · `source`
- **输出**列：`id` · `guid` · `field` · `target`，**顺序与 `id` 必须原样**；`target` 留空 ⇒ 该条保持原文
- 于是"翻译器"可以是一个 exe、一段脚本、一次 `ollama` 调用、一张人工填的表 —— **只要它能产出这个 TSV**。
- 为什么是 TSV 而不是 JSON：**可 diff、可人工编辑、可流式、任何语言都好生成**（翻译引擎基本都不是 PowerShell）。

## 1. 两条路：先改文本，必要时才改图

| | **改文本**（先做这条） | 改图 |
|---|---|---|
| 动什么 | 存档里的 `Nickname` / `Description` / `GMNotes` | `CustomDeck.FaceURL` 指向的卡图 |
| 能翻到 | 卡名 · **卡面文字**（这类 mod 的 `description` 往往就是整张牌面）· 备注 | 画**在图里**的文字（不少 mod 把规则烤进图） |
| 代价 | 小、可回滚（只动文本字段，不碰桥接、不用重烤） | 大：OCR ＋ 重绘 ＋ 换 URL ＋ 重烤存档 |
| 谁做 | 本仓库提供导出/回写两侧 | 外部件（OCR 与重绘），本仓库暂不提供 |

## 2. 部署矩阵：引擎怎么选（**按本机可行性排序**）

| 方案 | 依赖 | 离线 | 说明 |
|---|---|---|---|
| ⭐ **Transformers.js**（`@xenova/transformers`） | **只要 Node** | ✅ 模型首次下载后 | 与本仓库现有运行时一致（本来就只有 Node ＋ PowerShell）· 例 `Xenova/nllb-200-distilled-600M`（多语）或 `Xenova/opus-mt-en-zh` · CPU 能跑 |
| **Argos Translate** | Python | ✅ | 质量稳 · 模型约 100 MB/语对 · 有 CLI · 批量快 |
| **LibreTranslate** | Python 或 Docker | ✅ | 带 HTTP API（多进程友好）；Argos 的上层封装 |
| **本地 LLM**（ollama 等） | 独立运行时 | ✅ | 质量最高，**而且仍然零 token**（本地推理）；要 GPU 才快 |
| 手工 / 半自动 | 无 | — | 直接给人编 TSV —— 这本身就是一个"可用选项" |
| ❌ 云翻译 API / 大模型逐条翻 | 网络 ＋ 计费 | ❌ | **与"省 token"直接冲突** ⇒ 不作为默认路径 |

⚠️ **本机实测现状（2026-10-13）**：这台机器**只有 Node**（`python` 是 Microsoft Store 的假 stub，没有 pip / docker / ollama / tesseract）⇒ **上表只有"依赖存不存在"是实测的，配方本身尚未在本机跑过**。
**一条命令就能验证那条首选路线**（在你那台能出网的终端跑）：

```powershell
npm i @xenova/transformers
node -e "const {pipeline}=require('@xenova/transformers');pipeline('translation','Xenova/opus-mt-en-zh').then(async t=>console.log((await t('Draw two cards.')).translation))"
```

出中文 ⇒ 这条路通，把它包成"吃 TSV 吐 TSV"的小脚本即可接上接口。

## 3. 为什么这样切（取舍，都是付过代价的）

- **引擎不进仓库**：体积大、语对多、更新快；绑进来等于让本仓库变成它们的发行版。我们只出**两侧不依赖引擎的脚本** ＋ **一个文本接口**。
- ⛔ **绝不重新序列化整个存档**（2026-10-12 实测）：`JavaScriptSerializer` 会把字段丢掉/乱序 ⇒ **静默毁存档**。所以回写走**字符串级替换**，改完**回读校验**产物仍是合法存档 JSON（这条机制当晚已在存档副本上验过）。
- **默认不直接写进 `Saves\`**：那是工作区外的路径（本沙箱要提权）。让回写落在你指定的位置，放回由你决定 —— 这也是"人拍板"的一部分。
- **不需要重烤、不碰桥接**：本方案只改文本字段，与 `lua\dsh_global.lua` 无关。
- **不替人做选择**：翻译质量、要不要翻某一类字段、要不要留原文对照 —— 都是使用者的决定，接口只保证"你能接上"。
