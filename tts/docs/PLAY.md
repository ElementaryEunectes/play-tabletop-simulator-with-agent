# PLAY.md —— **通用**每回合卡（对任何 TTS mod 都成立）

> **什么时候读我**：每一回合。本文件只讲"**怎么动**"：控制台动词 · 哨兵/叫醒 · 状态页维护纪律。
> **这一局的状态**在 `local\games\<游戏>\STATE.md`（**不进仓库**）；**当前是哪一款**见 `local\games\_current.md`。
> ⛔ 规则 / 技能 / 卡面 / 比分 / guid **一律不进本文件** —— 那些是"某一款游戏"的内容。

## 通用动作（动词 · 哨兵 · 状态页维护）

> 规则/技能/骰面 = 该游戏的 `local\games\<游戏>\FLOW.md`（⛔ **不进仓库**）· TTS 通用坑与**工具清单** = `TTS_RULES.md` · **本节不重复它们**。

### 一回合（照抄）

1. **一条命令开局**：**有控制层的游戏**用 `tts\play.ps1 turn`（一次给齐：盘面 ＋ 我的骰面（只读）＋ 可打招式 ＋ 笔记本尾条）；
   ⚠️ **没有控制层的游戏**（`local\games\<游戏>\control\play.ps1` 不存在）用 `tts\play.ps1 status` —— 它给出**与游戏无关**的四项（桥接版本 · 物件数 · 在位玩家 · 轮到谁），
   然后按该游戏 `STATE.md` 自己拼动词。⛔ 别照抄 `turn`：没有控制层时它会明确报 `NO PART`。
2. 该我走：照该游戏 `STATE.md`（`local\games\<游戏>\`）的「待办」＋ 它的 `FLOW.md` 技能表 ⇒ **一条命令一个阶段**。
3. **摆决策**：把「选项 ＋ 代价」摆给玩家等他点（⛔ 绝不替他拍）。
4. **表响应**：他每次宣告 = 我的响应窗口 ⇒ 明说"**出牌 / 不出牌**"。
5. **写回 STATE**：只改「当前」块与待办，过去回合压成一行；报字节数（≤5KB）。
6. **挂哨兵**等「结束回合」（见下），**别轮询**。

### 控制台动词（`tts\play.ps1 <动词>`，一条命令 = 一个阶段）

| 动词 | 作用 |
|---|---|
| `turn` | ⭐ 回合开局一条命令：盘面 ＋ 我的骰面 ＋ 可打招式 ＋ 笔记本尾条（**全只读**） |
| `status` | 只要盘面：物件数 ＋ 双方 HP/CP ＋ 状态 token |
| `income -Seat moon -Apply` | 收入（+1 CP；本模组收入**不抽牌**）。**不加 `-Apply` 只报"会变成几"** |
| `roll -Seat moon [-Roll] [-Lock 1,3]` | 进攻掷骰；**不加 `-Roll` 只读** |
| `attack -Seat scar -Ability '<名>' [-Apply] [-Damage N]` | 判定/结算**他**的技能（不带 `-Apply` 只查表） |
| `defense -Seat moon [-Apply -Incoming N]` | 我的防御；**不加 `-Roll` 只读** |
| `say -TextFile <utf8>` | 往笔记本发一行（中文**必须**走文件） |

⚠️ **别 read 控制层入口本体** —— 当前游戏的控制层在 `local\games\<游戏>\control\`（`play.ps1` ＋ `dice`/`rules`/`verbs` 等模块，**要改哪块就读哪块**）；仓库里的 `tts\play.ps1` 只是**分发器**（解析 `GAME=` ⇒ 把参数原样转发）。分层与契约 ⇒ `TTS_RULES.md` §二 方框。技能数据 `cache\<game>_rules.json`（= `$DshGameRules`），卡面 `tts\card.ps1 -Q '<名>'`。
⚠️ `setLock` 坏了（`cannot convert userdata to Boolean`）⇒ 重掷只能逐颗 `ds.ps1 -Do act:<骰guid>:roll`。
⚠️ **骰子**：`roll.ps1` 必须明说 `-Roll`/`-NoRoll`（裸调用 `exit 2`）；**判定以玩家报的为准**。
⚠️ **结算顺序**：宣告 → 先问他改不改骰 → 防御掷骰 → 才扣血。**数字没谈定先跑 `-Apply -WhatIf`**（打印 `WILL WRITE` 但不写）；`-Apply` 真写后脚本自己回读，不一致即 `BAD DATA`。

### 哨兵 / 叫醒（细节见 `TTS_RULES.md`；**不跨会话继承**）

- **回合交接（本仓库现行做法，2026-10-11 定稿）**：
  - ⭐ **机制（玩家定；含其更正）**：按键把棋子挪到 **「存档颜色」的下一位** 的手牌位置 ⇒ **下一位若仍在本侧，棋子就挪回原地**（看着没反应、其实颜色已前进）⇒ 对面要**再按一次**。
  - ⛔ **"改它的颜色"我们做不到（四条路全试尽，2026-10-11）**：
    ① `callx`／`Object.call` ⇒ **TTS 失联**（两次实测）；② `messageID 3` 里改它的函数 ⇒ 跑在**空环境**且**污染它的行为**（F13）；
    ③ 外部写 `o.script_state` ⇒ **只生效一瞬**，随后被它自己的 `onSave`（用运行时颜色）**覆盖**（实测：同脚本内写后读回 `["Brown"]`，几秒后另一个脚本读到 `["Teal"]`）；
    ④ 改它的 `Name` ⇒ 只影响**轮转范围**（空名字会跑到 `Red` 这类空座位）。
  - ✅ **我们能做的**：**写位置** —— `tts\tr.ps1 -To mine|player`（唯一稳定生效、且 `turn_side.ps1` 真正读取的量）。**代价**：它的颜色与位置可能不同步 ⇒ 玩家**可能要点两次**才换边（**玩家 2026-10-11 明确接受**）。
  - **玩家侧**：按那枚 **Turn Tracker** 的按钮。**判定以位置为准、不以它的颜色为准。**
  - ⚡ **快链（2026-10-11 定稿，延迟 ~2-4 s；此前 ~33 s）**：常驻作业 `tts\tools\turn_poller.ps1`（**每 2.5 s** 读一次位置，**变化才写** `cache\turn_side.txt`）＋ **file 哨兵**（`pattern=^mine`，inotify 推送 **<1 s**）⇒ 检测 **~0.5-3.3 s**（实测 468 ms）。我交还 `tts\tr.ps1 -To player` **~0.9 s**（此前 12.9 s —— 那是 `exec_script.ps1` 空等回执窗口，已改成**收到回执即退出**）。
    ⚠️ **轮询器是后台作业、不跨会话** ⇒ 新会话要重跑上面那条命令并**重挂 file 哨兵**（旧的 `command` 哨兵每 20 s 一次，已被取代）。
    ⛔ **重挂 file 哨兵必须显式给 `max_fires`** —— 不写就默认 **1 次**、触发后**自动结束**（2026-10-11 真踩过：自测那一下就把订阅耗掉了，快链静默失效）。本仓库用 **`max_fires=500`**。
    ⛔ **但"永久防重复"靠的是模式本身、不是 `max_fires`**（玩家定的）：`^player`＝该你行动、`^mine`＝轮到我，每次触发都在"上一条指令**执行完毕**"之后才被推送 ⇒ 不会在**同一动作**上重复触发（同一文件内容不会再次产生"no-match→match"边沿，只有它**再次变化**才会），所以不会重复执行，也**不需要动作完成后再重挂**。
  - 📊 **一轮交接的延迟拆解（2026-10-11 实测，供以后判断"慢在哪"）**：
    ① 玩家按键 ⇒ 轮询器检测到 **~2.5 s**（轮询间隔）；
    ② 检测到 ⇒ **我真正开始处理 ~23 s** ← ⚠️ **平台唤醒投递的固有延迟，我们改不了**；
    ③ 我开始 ⇒ 棋子回到玩家侧 **~1.2 s**（`tr.ps1`，曾因 `exec_script.ps1` 空等回执窗口而高达 **12.9 s**，已修）。
    ⇒ **总感知 ~25 s**，**其中 23 s 不在我们手里**。⇒ 结论：**真对局就用这个**（我的回合本来就要思考），**不要**改成"轮询器自动交还"——那等于**替我把回合跳过**。
  - **判定**：`tts\tools\turn_side.ps1` 读棋子 `z` 的符号（校准档 `zMine=+15 / zPlayer=−15`；语义由玩家当面确认）。⛔ **别再用 `command` 哨兵做回合检测**（平台探测实际 ~20 s 一次，是当时延迟的主因）。
  - **体检**：`tts\tools\tracker_read.lua`（经 `exec_script.ps1`）一次读出 `POS / SAVED_STATE / LIVE_COLOR / LOCKED / NAME`。
  - ⛔ **别再用 `callx`/`Object.call` 驱动别的 mod**（会把 TTS 弄失联）；⛔ **别在 `messageID 3` 里改别人物件的函数**（⇒ `VALIDATION.md` F13）。
  - ⚠️ 那枚棋子的 **`Name` 必须写着颜色顺序**（本机 `Brown Teal`）—— 它**文档要求**的配置；清空会让它按 10 色表轮转、跑到 `Red` 这类**空座位**。
- ⛔ **"我点不了那个按钮"的判定与理由只有一处**：`TTS_RULES.md` §四 —— **别处不要再复述**；哪天它能被按下去，只改那一处。
- 新会话**必须重挂**哨兵（编号每会话不同，先 `sentinel_list`）。
- 收工：`sentinel_cancel` ＋ kill 后台作业。

### STATE 维护

- ≤5KB · **同一时刻只允许一个写入者**（改前先 read，改后报字节数）· ⛔ 不放规则/坐标常量/工具用法。
